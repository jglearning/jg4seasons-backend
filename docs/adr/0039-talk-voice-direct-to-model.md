# 0039. 프리토킹 음성은 브라우저와 모델이 직접 연결, 서버는 임시 키와 지시문만

- 상태: 결정 · 날짜: 2026-11-25

## 배경
- 학생이 레벨 캐릭터와 3분 동안 영어로 말하는 기능(1단계 시연용)
- 실시간 음성 모델은 말한 시간·들은 시간만큼 과금. 지연이 길면 대화가 끊겨 들림
- 운영은 앱 서버 하나. 음성 중계에 쓸 WebSocket·미디어 서버 없음
- 지시문(레벨 기준·회차 단어·안전 규칙)은 서버가 정해야 함. 브라우저가 지어내면 학생이 바꿀 수 있음

## 선택지
### A. 브라우저 ↔ 모델 직접(WebRTC), 서버는 지시문을 묶은 임시 키만 발급
- 장점: 음성이 서버를 지나지 않아 지연·서버 부하 없음. 서버 코드가 작음(발급 POST 하나)
- 단점: 서버가 대화 내용·사용량을 직접 못 봄(브라우저가 보낸 값만). 연결된 브라우저가 지시문을 바꿀 수 있음. 시간 제한을 서버가 끊을 수 없음
### B. 서버 중계(브라우저 ↔ 서버 ↔ 모델)
- 장점: 사용량·내용을 서버가 직접 집계. 시간 제한을 서버가 끊음. 지시문을 서버만 바꿈
- 단점: 음성 스트림을 서버가 계속 들고 있음(연결 수만큼 메모리·대역폭). 지연 증가. 미디어 처리 코드 추가
### C. 음성인식 → LLM → 음성합성(서버에서 차례로)
- 장점: 단계마다 모델을 바꿀 수 있음. 글자 기록이 서버에 남음
- 단점: 단계마다 지연이 더해져 대화가 끊겨 들림. 구현량이 가장 큼

## 결정
A.

| 항목 | 값 |
|---|---|
| 서버가 하는 일 | 세션 행 저장(`talk_session`), 지시문 조립(`prompts/talk/v1/`), 임시 키 발급 |
| 임시 키에 묶는 것 | 모델, 지시문, 음성, 학생 말 글자 변환 모델, 침묵 5초 뒤 다시 묻기, 키 수명 60초 |
| 브라우저가 보내는 것 | 주제 code(`lesson`·`day`·`likes`), 음성 code(`female`·`male`)만 |
| 끝낼 때 | 서버가 준 마무리 신호 문장(`closingInstruction`)을 브라우저가 세션에 넣어 캐릭터가 인사하고 끝냄 |
| 모델·음성 이름 | 설정값(`jg4seasons.talk.realtime.*`), 키 없이 배포하면 발급 꺼짐(생성만 503) |
| 하루 한도 | 학생당 3회(학원 날짜), 발급에 실패한 세션은 세지 않음 |

## 근거
- 시연 범위에서 지연과 구현량이 가장 작음
- 지시문을 서버가 조립해 키에 묶으므로 기본 대화는 서버가 정한 규칙대로 시작
- 세션 행과 지시문 버전(`prompt_version`)이 남아 비용 실측·전후 비교 가능

## 포기한 것
- 서버 쪽 사용량 집계. 1단계는 브라우저가 알려준 사용량을 그대로 저장(신뢰 불가)
- 지시문 고정. 연결된 브라우저가 세션 설정을 바꾸는 메시지를 보내면 지시문이 바뀜(서비스 문서에 서버 쪽 고정 수단 없음)
- 서버가 시간 제한으로 끊기. 서비스의 세션 최대 길이는 60분 고정이라 180초는 브라우저 타이머만 지킴. 마지막 방어는 서비스 콘솔의 월 사용 한도

## 재검토 조건
- 실제 학생에게 열기 전(서버 쪽 사용량 집계·지시문 변경 감지 필요)
- 리허설 실측으로 3분 1회 비용이 구독 가격을 넘을 때
- 지시문 변경·시간 초과 사용이 실제로 보일 때
- C(음성인식 → LLM → 음성합성)와 같은 대화로 지연·분당 비용을 비교한 뒤
