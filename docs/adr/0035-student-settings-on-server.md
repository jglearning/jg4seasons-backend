# 0035. 학생이 고른 목소리를 서버에 저장한다 — 폰을 바꿔도 남고, 보낸 값만 바꾼다

- 상태: 결정 · 날짜: 2026-11-21

## 배경
학생은 지문마다 목소리 네 개 중 하나를 골라 듣는다(0027). 고른 목소리는 다음 지문, 다음 회차, 앱을 다시 열었을 때도 그대로여야 한다.

서버에는 학생 설정을 둘 자리가 없다. 화면이 기기에만 저장하면 폰을 바꾸거나 다시 입장할 때마다 처음 값으로 돌아간다. 학생은 기기를 자주 바꾼다.

지금 저장할 값은 고른 목소리 하나다. 설정은 앞으로 늘 수 있다(재생 속도 등). 다만 지금 그것을 저장하는 화면은 없다.

정할 것은 셋이다. 어디에 저장하나, 어떻게 고치나, 기본값은 누가 정하나.

## 선택지
### 저장 자리
#### A. 사용자 표의 JSON 칸
- 장점: 설정이 늘어도 스키마를 바꾸지 않는다. 학원 표에 같은 방식의 칸이 이미 있다
- 단점: 값 검증이 코드에만 있다. 잘못된 값을 DB가 막지 못하고 집계가 불편하다
#### B. 사용자 표의 타입 있는 칸
- 장점: 표가 늘지 않는다. DB가 값을 제약한다
- 단점: 로그인할 때마다 갱신되는 사용자 행에 설정 쓰기가 겹친다. 사용자 표가 설정 수만큼 넓어진다
#### C. 새 표, 설정마다 타입 있는 칸
- 장점: DB가 값을 제약한다. 사용자 행을 건드리지 않는다. 설정이 늘 때의 변경이 마이그레이션 이력으로 남는다
- 단점: 표가 하나 는다. 설정 하나에 마이그레이션 한 줄이 필요하다

### 수정 방식
#### A. 전체 교체
보낸 값으로 설정 전체를 바꾼다.
- 장점: 뜻이 단순하다
- 단점: 설정이 늘어난 뒤, 업데이트되지 않은 옛 화면이 자기가 아는 칸만 보내면 새 설정이 지워진다. 홈 화면에 추가한 앱은 옛 버전이 오래 남는다
#### B. 부분 수정
보낸 칸만 바꾼다.
- 장점: 옛 화면과 새 화면이 함께 있어도 서로의 설정을 지우지 않는다
- 단점: "보내지 않음"과 "지움"을 구분해야 한다

### 기본값
#### A. 서버가 채운다
- 장점: 화면이 늘 값을 받는다
- 단점: 학생이 고른 것과 기본값을 구분할 수 없다. 기본 목소리를 바꾸려면 서버를 고쳐야 한다
#### B. 화면이 정한다
- 장점: "고른 적 없음"이 값으로 남는다. 기본값은 화면의 결정으로 둔다
- 단점: 화면마다 기본값 처리가 필요하다

## 결정
저장은 C, 수정은 B, 기본값은 B.

1. **새 표에 둔다.** 학생 한 명에 한 행이고 설정마다 칸을 둔다. 지금은 목소리 칸 하나다. 값은 DB 제약으로 네 목소리 또는 비어 있음만 허용한다. 행은 처음 저장할 때 만들고, 조회만으로는 만들지 않는다.
2. **보낸 칸만 바꾼다.** 보내지 않은 칸은 그대로 두고, null을 보내면 그 칸만 비운다. 빈 본문은 아무것도 바꾸지 않는다. 같은 본문을 다시 보내도 결과가 같다.
3. **응답은 늘 설정 전체다.** 화면이 받은 값으로 통째로 바꿀 수 있다.
4. **기본값은 화면이 정한다.** 비어 있음은 "고른 적 없음"이다.
5. **학생만 쓴다.** 교사·관리자·운영자에게는 고를 목소리가 없다.
6. **목소리 값은 네 목소리 중 하나면 받는다.** 그 학생 반의 레벨에 묶지 않는다. 반을 옮겨도 저장한 값이 무효가 되지 않는다.
7. **나중에 쓴 값이 이긴다.** 두 기기에서 동시에 바꿔도 충돌을 알리지 않는다. 처음 저장이 동시에 와도 행은 하나만 생긴다.

완료 판정과는 무관하다. 어느 목소리로 들었는지는 청취 기록이 정한다(0034).

## 근거
- 수정 방식은 나중에 바꾸려면 계약을 깨야 한다. 설정이 하나뿐인 지금 부분 수정으로 정해 두는 비용은 전체 교체와 거의 같다.
- 화면이 여러 버전으로 동시에 살아 있는 환경에서 전체 교체는 옛 화면이 새 데이터를 지우는 길을 연다.
- 저장하는 값이 정해진 목록 중 하나라면 DB가 막는 쪽이 코드만 믿는 쪽보다 안전하다. 스키마가 없는 것이 아니라 스키마를 안전하게 바꿀 수 있는 것을 확장으로 본다.
- 사용자 행은 로그인마다 갱신된다. 설정을 따로 두면 그 행과 쓰기가 겹치지 않는다.

## 포기한 것
- 설정이 하나 늘 때마다 마이그레이션과 칸 하나가 필요하다.
- 표가 하나 는다.
- 두 기기에서 서로 다른 값을 거의 동시에 저장하면 한쪽이 조용히 덮인다. 잃는 것은 설정 값 하나다.
- 설정을 언제 누가 바꿨는지는 남기지 않는다.

## 재검토 조건
- 설정이 열 개를 넘거나 화면이 임의의 키를 저장해야 하면 저장 모양(A)을 다시 본다.
- 동시에 바꾼 설정을 잃는 일이 실제로 문제가 되면 버전 번호를 넣어 충돌을 알린다.
- 교사·관리자 설정이 필요해지면 대상을 넓힌다.
