# 0032. 운영자는 학원 역할 계층 밖에 두고 시스템 API만 쓴다

- 상태: 결정 · 날짜: 2026-11-11 (0031 결정 7의 구현, API 명세의 역할 계층 변경)

## 배경
- 0031 결정 7로 운영자(최상위 역할)가 학원 만들기·교재 사용권 지정·사용 현황을 다룬다. 이 역할은 스키마에 있었지만 로그인·권한에 쓴 적이 없다.
- 운영자 계정은 어느 학원에도 속하지 않는다(학원 칸이 비어 있다). 데이터는 학원 단위로 나뉘고(0004), 학원 범위 API는 로그인 토큰의 학원 값으로만 범위를 정한다.
- API 명세의 역할 계층은 "운영자 > 학원관리자 > 교사"였다. 이대로 운영자가 로그인하면, 교사·학원관리자 API의 권한 검사를 통과한 뒤 학원 값이 없는 채로 안으로 들어간다.
- 지금은 학원 값을 읽는 공용 함수가 값이 없으면 401로 끊는다. 하지만 엔드포인트마다 그 함수를 거친다는 보장이 사람의 습관뿐이다. 하나라도 다른 길로 학원을 정하면 500이 나거나 학원 범위가 비게 된다.

## 선택지
### A. 계층을 유지하고, 학원 값이 없으면 학원 API에서 401
- 장점: 운영자가 나중에 학원 화면을 대신 볼 길을 남긴다
- 단점: 학원 범위 API 전부가 "학원 값 없음"을 올바르게 다뤄야 안전하다. 새 엔드포인트가 생길 때마다 같은 확인이 필요하다
### B. 운영자를 계층에서 빼고, 시스템 API만 허용
- 장점: 권한 검사 한 곳(역할 계층)에서 운영자가 학원 API에 들어가는 길이 닫힌다. 학원 범위 코드는 "학원 값이 늘 있다"는 전제를 그대로 쓴다
- 단점: 운영자가 학원 화면을 직접 볼 수 없다

## 결정
**B.**
1. 역할 계층은 "학원관리자 > 교사"만 남긴다. 운영자는 어느 역할도 포함하지 않는다.
2. 운영자는 시스템 API(학원 만들기·목록·상세, 교재 사용권 지정)와 공통 인증(로그인·갱신·로그아웃·내 정보)만 쓴다. 교사·학원관리자·학생 API는 403이다.
3. 운영자 토큰에는 학원 값이 없다. 내 정보와 로그인 응답의 학원은 비어 있다(null).
4. 운영자 계정은 실행 환경의 설정값으로 만든다. 운영자가 한 명도 없을 때만 만들고, 이미 있으면 설정값을 읽지 않는다. 비밀번호는 저장소에 두지 않는다. 값이 없으면 경고만 남기고 서버는 뜬다(운영자가 없어도 학원들은 그대로 돈다).
5. 운영자가 만든 학원의 첫 학원관리자는 그 학원 계정이다. 학원 안의 일은 그 계정으로 한다.

## 근거
- 운영자 계정 하나로 모든 학원의 사용권을 바꿀 수 있다. 이 계정이 학원 데이터 API까지 열면 비밀번호 하나의 피해 범위가 모든 학원의 학생 기록으로 넓어진다.
- 학원 범위 검사는 0004 이후 "토큰의 학원 값"을 전제로 쌓였다. 그 전제가 깨지는 계정을 들이는 대신 들어오는 문을 닫는 편이 검사할 곳이 적다.
- 운영자가 하는 일(학원 만들기, 권별 기간·학생 수)은 학원 안의 데이터를 읽지 않고도 할 수 있다. 사용 학생 수는 시스템 API가 숫자로만 보여 준다.
- 운영자가 없을 때 서버를 멈추면, 설정값 하나를 빠뜨린 배포가 이미 쓰고 있는 학원까지 멈춘다.

## 포기한 것
- 운영자가 학원 화면(진도표·명단·청취 현황)을 대신 보는 것. 필요하면 그 학원 관리자 계정으로 본다.
- 운영자 계정 여러 명 관리 화면. 설정값으로 첫 한 명만 만든다.

## 재검토 조건
- 운영자가 학원 데이터를 직접 봐야 하는 지원 업무가 생기면(학원을 고르는 범위 지정과 감사 기록을 함께 다시 본다).
- 운영자가 여러 명 필요해지면.
