# 0010. flush 단일 엔드포인트, 세션은 upsert, sendBeacon은 바디 토큰

- 상태: 폐기(→ 0018) · 날짜: 2026-11-01

## 배경
폰에서 화면 꺼짐·탭 이탈 시 마지막 청취 구간을 반드시 보내야 한다. `sendBeacon`은 커스텀 헤더를 실을 수 없다.

## 선택지
### A. flush 한정으로 바디에 access 토큰 허용
- 장점: sendBeacon으로도 인증 가능
- 단점: 토큰을 JS가 다뤄야 함
### B. 쿠키 인증
- 장점: 토큰이 JS에 노출되지 않음
- 단점: 배포 구성(같은 도메인)을 함께 정해야 함

## 결정(당시)
A. flush 단일 엔드포인트, 청취 세션은 첫 flush에서 upsert, sendBeacon은 바디 토큰.

## 근거
당시에는 인증 방식이 헤더 토큰이었다.

## 폐기 이유
"토큰을 JS에서 다루지 않는다" 규칙과 충돌한다. 같은 도메인 배포 + HttpOnly 쿠키면 sendBeacon이 쿠키를 자동 전송하므로 바디 토큰이 필요 없다 → 0018. "flush 단일 엔드포인트 + 세션 upsert" 부분은 유지한다.
