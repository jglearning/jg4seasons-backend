# 0007. 완료 판정 규칙은 데이터(`completion_rule`)로

- 상태: 결정 · 날짜: 2026-11-01

## 배경
"들었다"의 기준(몇 %, 어떤 트랙)은 교육적 판단이라 바뀔 수 있다. 운영 측: "일단 추천대로, 언제든 바꿀 수 있으니."

## 선택지
### A. 기준을 코드 상수로
- 장점: 단순
- 단점: 기준 변경마다 배포
### B. 레벨별 규칙 행 + 규칙 해석기
- 장점: 배포 없이 변경. 레벨별로 다른 필수 트랙 표현 가능
- 단점: 규칙 형식(JSON)을 설계·검증해야 함

## 결정
B. 레벨별 `coverage_threshold`(기본 0.9)와 `required_tracks` JSON. 코드는 규칙 해석기(`CompletionRuleEvaluator`) 하나.

## 근거
기준 변경에 배포가 필요 없고, 레벨별로 다른 활동(예: 낮은 레벨은 0.8배속도 인정, 높은 레벨은 1.2배속 활동)을 표현할 수 있다.

## 포기한 것
규칙이 코드에 보이는 단순함. 임계값 리터럴이 코드에 흩어지지 않도록 아키텍처 테스트로 막는다.

## 재검토 조건
반 단위 예외(특정 반만 1.2배속 필수)가 생기면 반 단위 오버라이드.
