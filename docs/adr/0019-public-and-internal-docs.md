# 0019. 문서는 공개 `docs/`와 내부 문서로 분리

- 상태: 결정 · 날짜: 2026-11-01

## 배경
저장소는 공개(포트폴리오)다. 설계서에는 사람 이름, 고객 정보, 내부 일정이 들어 있다.

## 선택지
### A. 설계서를 정제해 전부 공개
- 장점: 문서가 한 곳
- 단점: 문서를 고칠 때마다 정제 비용. 실수로 노출될 위험
### B. 공개 / 내부 분리
- 장점: 정제 대상이 ADR·API 계약으로 좁아짐
- 단점: 내부 문서는 저장소 밖(로컬)에만 있음

## 결정
B. `docs/`(커밋) = ADR(이름·URL 제거, 번호 재부여)·`api/openapi.json`·README. 내부 문서 디렉터리(git 제외) = 설계서 원본·작업 기록·계획·인수인계·포트폴리오 기록. 공개 문서 작성 후 금지어를 grep한다.

## 근거
설계서를 공개용으로 정제하는 비용보다 분리가 싸다.

## 포기한 것
설계 과정 전체의 공개.

## 재검토 조건
다른 학원에 납품하며 문서를 전달해야 하면 내부 설계서에서 납품용을 따로 뽑는다.
