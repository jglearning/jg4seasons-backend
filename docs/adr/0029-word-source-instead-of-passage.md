# 0029. 단어에는 나온 지문 대신 출처(어휘책 / 추가 어휘)를 저장한다

- 상태: 결정 · 날짜: 2026-11-10

## 배경
- 0025는 단어마다 나온 지문 번호를 두고, 카드 학습 목록 탭을 지문별로 거르기로 했다. 학생 API의 단어 응답에도 지문 번호(`passageNo`, 1~6)가 필수로 있다.
- 실제 자료(0027 결정 6)로 넣은 단어에는 나온 지문 정보가 없다. 단어는 회차 단위 목록이고, 두 곳에서 온다.

| 출처 | 내용 | 음원·예문 해석 |
|---|---|---|
| 어휘책 | 그 강의 단어 → 숙어(교재 순서) | 녹음 자료에도 있는 단어만 있음 |
| 녹음 자료의 회차 어휘 | 어휘책에 없는 것만 맨 뒤에 붙음 | 있음 |

- 가져올 때 두 목록을 합치기만 하고, 어느 쪽에서 왔는지는 저장하지 않았다.
- 지금 데이터(124회차, 단어 8,831개)에서 음원이 없는 단어는 모두 어휘책에만 있는 단어다. 그래서 지금은 "음원이 없으면 어휘책 단어"로 짐작할 수는 있다. 하지만 어휘책 단어 음원은 나중에 만들 예정이다(0027 포기한 것).

## 선택지
### A. 출처를 단어마다 저장한다
`word.source`에 `book`(어휘책의 단어·숙어) 또는 `extra`(어휘책에 없는 회차 어휘)를 넣는다. 가져오기 스크립트가 합칠 때 정하고, 가져오기 명령이 저장한다.
- 장점: 어휘책 음원이 들어와도 구분이 그대로다. 목록 탭을 출처로 거를 수 있다
- 단점: 마이그레이션 하나와 가져오기 변경이 필요하다. 운영에서 가져오기를 한 번 다시 해야 한다
### B. 구분 없이 지문 번호만 뺀다
- 장점: 작업이 가장 작다
- 단점: 목록 탭에 거를 기준이 없다
### C. 음원 유무로 출처를 대신한다
- 장점: 스키마를 바꾸지 않는다
- 단점: 어휘책 음원이 들어오는 순간 의미가 바뀐다. 음원 유무는 응답의 `audio`로 이미 알 수 있다

## 결정
**A.**
1. `word.source`(`book` / `extra`)를 추가한다(V8, 필수).
   - `book`: 어휘책 그 강의 단어·숙어. 녹음 자료에도 있어 그쪽의 뜻·예문·음원을 쓰는 단어도 `book`이다
   - `extra`: 어휘책에 없고 녹음 자료의 회차 어휘에만 있는 단어
2. 가져오기 스크립트가 출처를 manifest에 적고, 가져오기 명령이 저장한다. 출처가 다르면 그 회차는 바뀐 것으로 본다. 단어는 회차 안 순서로 짝을 맞춰 그 행만 고치므로 단어 id, 음원, 학습 기록은 그대로다.
3. 학생 단어 응답에서 `passageNo`를 빼고 `source`를 넣는다. 카드 학습 목록 탭은 지문별 대신 출처별로 거른다(0025 일부 변경).
4. 단어가 나온 지문(`word.passage_id`)은 칸을 남기되 쓰지 않는다. 지문 정보가 있는 자료가 오면 다시 쓴다.

## 근거
- 출처는 자료를 합치는 순간에만 확실히 안다. 그때 적어 두지 않으면 나중에 되살릴 방법이 짐작뿐이다.
- 음원 유무와 출처는 다른 사실이다. 한 칸으로 두 가지를 나타내면 한쪽이 바뀔 때 다른 쪽이 틀린다.
- 어휘책 단어는 수업에서 외우는 목록이고, 추가 어휘는 녹음 자료에서 더 나온 단어다. 학생과 교사 모두 이 구분을 교재로 알아본다.
- 가져오기는 이미 회차 단위로 멱등하고 단어를 제자리에서 고친다. 다시 실행하는 비용이 작다.

## 포기한 것
- **지문별 단어 보기.** 자료에 지문 정보가 없다.
- **두 쪽에 다 있는 단어의 따로 표시.** `book`으로만 둔다. 학생에게는 "어휘책에 있는 단어"라는 사실이 중요하다.

## 재검토 조건
- 단어마다 나온 지문이 적힌 자료가 오면 `passage_id`를 채우고 지문별 보기를 다시 검토한다.
- 교사가 출처별 학습 결과(어휘책 단어 중 몇 개를 아는지)를 원하면 단어별 기록(0025 재검토 조건)과 함께 검토한다.
