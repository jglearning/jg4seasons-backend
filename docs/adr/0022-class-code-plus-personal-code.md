# 0022. 학생 입장은 가입 코드(반) + 개인 코드(4자리)로 바로 본인 홈

- 상태: 결정 · 날짜: 2026-11-03 · 대체: 0003

## 배경
교사 피드백(11/3): 이름 찾기가 길다, 로그인하면 바로 본인 페이지로 가야 한다. 앞서 "반 코드와 개인 코드 둘 다 필요"라는 의견도 있었다(11/2).

## 선택지
### A. 개인 코드가 PIN만 대신(이름 선택 유지)
- 장점: 0003에서 바뀌는 것이 적음
- 단점: 이름 찾기가 그대로 남음
### B. 개인 코드가 이름 선택 + PIN을 대신
- 장점: 입력 두 칸으로 끝. 이름 목록을 내려주지 않아 반 명단이 밖으로 새지 않음
- 단점: 개인 코드를 학원 안에서 고유하게 발급·관리해야 함
### C. 개인 코드 하나만(반 코드 없음)
- 장점: 입력 한 칸
- 단점: 학원 밖에서 개인 코드만으로 찍어 맞출 수 있음

## 결정
B. 교사가 명단을 등록하면 학생마다 숫자 4자리 **개인 코드**를 발급한다. 학생은 처음 한 번 가입 코드(반 공용 8자) + 개인 코드를 한 화면에 넣고 바로 본인 홈으로 간다. 이후 refresh 90일 자동 로그인. 로그아웃·기기 변경 때는 기기에 저장된 반으로 개인 코드만 입력한다. PIN 설정·변경 화면은 없다.

구현: `auth_identity.provider = personal_code`, `identifier = HMAC-SHA256(pepper, academyId + ":" + code)`, `UNIQUE(provider, identifier)` → 개인 코드는 학원 안에서 고유하고 조회는 1회다. 가입 코드로 반을 찾고, 개인 코드로 학생을 찾고, 그 학생이 그 반에 현재 소속인지 확인한다. 평문은 발급·재발급 응답에서만 보여 준다(DB에 평문 없음).

## 근거
입력 두 칸으로 끝나고, 4자리 숫자는 초등생도 외운다. 가입 코드가 있어 학원 밖에서 개인 코드만으로 찍어 맞출 수 없다.

## 포기한 것
- 가입 코드를 아는 사람(반 친구)이 4자리를 찍어 맞출 여지. 반 학생 30명이면 한 번에 맞힐 확률 0.3%.
  - 막는 것: (반, IP)당 5회 실패 → 10분 잠금, 반 전체 1시간 20회 실패 → 교사 화면 경고(인메모리 카운터, 단일 인스턴스 전제).
  - 한 사람이 하루 종일 찍으면 하루 1~2명꼴로 맞힐 수 있는 수준이라, 막기보다 교사가 알아채는 쪽으로 둔다.
  - 맞혀도 할 수 있는 것은 그 학생 학습 기록 보기·대신 듣기뿐이다(개인정보는 이름·학교·학년).
- 교사가 개인 코드를 "다시 보기"할 수 없다(재발급만). 평문 저장을 피하기 위해서다.

## 재검토 조건
- 교사가 "코드 다시 보기"를 자주 요구하면 암호화 저장(AES-GCM) 검토.
- 서버를 2대 이상으로 늘리면 실패 카운터를 DB나 Redis로.
- 실패 잠금 기준(5회/10분, 20회/시간)은 운영 후 조정(미결).
