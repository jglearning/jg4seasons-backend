# 0001. 기존 학원 관리 앱과 별도 서비스, 별도 계정

- 상태: 결정 · 날짜: 2026-11-01

## 배경
같은 AWS 계정에 기존 학원 관리 웹앱이 운영 중이고, 그 학생 DB를 재사용할 수 있었다. 이 앱은 여러 학원에 판매되는 교재의 부속 서비스다.

## 선택지
### A. 기존 앱의 모듈로 흡수
- 장점: 학생 DB·인증 재사용, 배포 하나
- 단점: 기존 앱은 한 학원 재원생 전용이라 사용자 집합이 다름. 다른 학원 학생을 받으려면 기존 앱 구조를 바꿔야 함
### B. 별도 서비스 + 계정 공유(SSO)
- 장점: 학생 로그인 한 번
- 단점: 두 앱의 사용자 집합이 달라 연결 규칙이 복잡함
### C. 별도 서비스 + 별도 계정
- 장점: 다학원 전제로 처음부터 독립. 두 앱이 서로의 장애·변경에 묶이지 않음
- 단점: 두 앱을 모두 쓰는 학생은 로그인을 두 번 함

## 결정
C. 같은 AWS 계정 안에서 별도 EC2·도메인.

## 근거
사용자 집합이 다르고(외부 학원 학생 포함), 다학원 전제라면 처음부터 독립시키는 편이 깔끔하다. 운영 측 결정(2026-10).

## 포기한 것
두 앱 사이의 단일 로그인.

## 재검토 조건
두 앱을 모두 쓰는 학생이 "로그인 두 번"에 불편을 호소하면 SSO 검토.
