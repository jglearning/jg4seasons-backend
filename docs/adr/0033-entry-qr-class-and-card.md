# 0033. 입장 QR — 반 QR과 학생 카드 QR을 함께 쓴다

- 상태: 결정 · 날짜: 2026-11-12 · 보완: 0022

## 배경
학생은 처음 한 번 가입 코드(반 공용 영숫자 8자)와 개인 코드(숫자 4자리)를 직접 입력한다(0022). 가입 코드는 헷갈리는 글자(0·O·1·I·L)를 빼고 만들지만, 초6~중3 학생이 폰으로 12자를 치는 단계라 첫 입장에서 막히기 쉽다.

입력을 줄일 재료는 이미 있다.
- 교사·관리자 반 목록 응답에 반의 가입 코드(`accessCode`)가 있다.
- 명단을 등록하거나 개인 코드를 재발급하면 응답에 개인 코드 평문이 한 번 나오고, 그 결과로 학생 카드(가입 코드 + 개인 코드)를 인쇄한다.

0022의 입장 방식(가입 코드 + 개인 코드, 실패 잠금)은 바꾸지 않고, 코드를 손으로 치는 단계만 줄인다.

## 선택지
### A. 반 QR만
반 목록에서 `/join#c=<가입 코드>` QR을 띄우거나 링크를 반에 공유한다. 학생은 개인 코드 4자리만 입력한다.
- 장점: 새 위험 없음(가입 코드는 원래 반에 공지하는 값). 카드가 없어도 쓴다
- 단점: 첫 입장에도 4자리 입력이 남는다
### B. 학생 카드 QR만
카드에 `/join#c=<가입 코드>&p=<개인 코드>` QR을 인쇄한다. 찍으면 두 칸이 채워진다.
- 장점: 첫 입장 입력 없음
- 단점: 카드를 잃어버리거나 집에 두면 다시 12자 입력. QR 사진이 퍼지면 그 학생으로 들어갈 수 있다
### C. 둘 다
카드를 나눠 준 첫 입장은 카드 QR, 카드 없이 기억된 반이 없는 기기에서는 반 QR + 4자리.
- 장점: 첫 입장 입력 없음, 카드가 없을 때도 12자를 치지 않는다
- 단점: 프론트 화면 두 곳(반 목록, 카드 인쇄)과 QR 진입 처리. 카드 QR의 위험은 B와 같다
### D. 1회용 입장 토큰
서버가 학생마다 한 번만 쓰는 토큰을 만들고 QR에 담는다.
- 장점: QR 사진이 퍼져도 한 번 쓰면 끝
- 단점: 토큰 발급·만료·소모 API와 저장이 새로 필요. 첫 입장에 실패하면 다시 인쇄해야 한다
### E. 교실 화면 QR + 교사 승인
교실 화면의 QR을 찍으면 교사 화면에 요청이 뜨고 교사가 승인한다.
- 장점: 코드가 없다
- 단점: 수업 중 교사 일이 늘고, 집에서 기기를 바꾸면 들어올 수 없다
### F. 소셜 로그인
- 장점: 학생이 이미 쓰는 계정
- 단점: 만 14세 미만 법정대리인 동의 절차가 필요하고 수집하는 개인정보가 늘어난다(0003에서 뺀 이유와 같음)

## 결정
C. 두 QR을 함께 쓴다. 서버 API·저장은 바뀌지 않는다.

| | 반 QR | 학생 카드 QR |
|---|---|---|
| 주소 | `/join#c=<가입 코드>` | `/join#c=<가입 코드>&p=<개인 코드>` |
| 만드는 곳 | 교사 반 목록·관리자 반 관리(가입 코드는 반 목록 응답에 있음) | 명단 등록·개인 코드 재발급 결과로 카드를 인쇄할 때 |
| 학생 입력 | 개인 코드 4자리 | 없음 |
| 쓰는 때 | 카드 없이, 기억된 반이 없는 기기(새 기기 등)에서 | 카드를 나눠 준 첫 입장 |

기억된 반이 있는 기기에서 로그아웃했다면 0022대로 개인 코드 4자리만 입력한다(QR 없이).

- 코드는 주소의 `#` 뒤(fragment)에 둔다. fragment는 서버로 보내지지 않아 서버·CDN 접근 로그와 Referer에 남지 않는다.
- 카드 QR은 개인 코드 평문이 있는 때(발급·재발급 응답)에만 만들 수 있다. 개인 코드는 다시 볼 수 없으므로(0022) 카드를 잃어버리면 재발급하고 새 카드를 인쇄한다.
- 로그인은 기존 학생 로그인 API와 실패 잠금을 그대로 쓴다. QR로 들어온 시도도 같은 카운터로 센다. 새 오류 code는 없다.
- 첫 입장 뒤에는 홈 화면에 추가하도록 안내한다(자동 로그인 90일은 0022 그대로).

### 입장 화면이 지킬 것(QR로 열렸을 때)
1. **먼저 읽고 지운다.** 로그인 여부와 상관없이 fragment를 먼저 읽고, 성공·실패와 상관없이 `history.replaceState`로 주소에서 지운다. 로그인된 사용자를 홈으로 보내는 처리는 그다음이다.
2. **형식에 맞는 값만 채운다.** `c`는 공백을 없애고 대문자로 바꾼 뒤 가입 코드 형식(영숫자 8자)일 때만, `p`는 숫자 4자리이고 `c`도 맞을 때만 칸에 채운다. 모르는 키는 무시한다. 하나라도 버렸으면 "QR을 끝까지 읽지 못했어요. 직접 입력해 주세요"를 보여 준다.
3. **자동으로 로그인하지 않는다.** 두 칸이 채워져도 학생이 "들어가기"를 한 번 누른다. 다른 사람이 카드를 찍기만 해도 들어가지는 일을 막는다.
4. **반 이름 표시는 선택이다.** 가입 코드 확인 API로 반 이름을 보여 줄 수 있지만, 이 API는 IP당 1분 10회로 세므로 같은 교실에서 한꺼번에 찍으면 429가 날 수 있다. 확인이 429·네트워크 오류로 실패해도 칸을 그대로 두고 "들어가기"를 막지 않는다(로그인은 가입 코드가 맞으면 이 한도를 세지 않는다).
5. **QR 값이 기억된 반보다 우선한다.** fragment에 `c`가 있으면 기억된 반(다시 들어오기 화면) 대신 코드 입력 화면을 보여 준다. 기억된 반은 로그인이 성공한 뒤에만 QR의 반으로 바꾼다.
6. **이미 로그인된 기기에서는 확인을 받는다.** "지금 ○○로 들어와 있어요. 다른 학생으로 들어갈까요?"를 보여 주고, 확인하면 아직 보내지 못한 청취 기록을 먼저 보낸 뒤 로그아웃하고 채운 값으로 입력 화면을 연다. 취소하면 채운 값을 버린다. 확인 없이 홈으로 보내면 다른 학생의 청취가 지금 학생의 기록으로 쌓인다.
7. **QR 값으로 실패하면 할 일을 알려 준다.** 오류 code는 그대로 두고 문구만 바꾼다: 카드 QR의 401은 "카드가 예전 것일 수 있어요. 새 카드를 받아 주세요", 반 QR의 가입 코드 확인 404는 "반 QR이 바뀌었어요. 새 QR을 받아 주세요". 401을 받은 같은 값은 칸이 바뀔 때까지 다시 보내지 않는다(버튼 비활성).

## 근거
- 첫 입장이 "카메라로 찍기 → 들어가기"로 끝나고, 카드가 없을 때도 4자리만 입력한다.
- QR에 담는 값은 이미 카드에 인쇄되는 값과 반에 공지하는 값뿐이라, 0022의 위험 판단(4자리 찍어 맞추기와 실패 잠금)은 바뀌지 않는다.
- 서버 변경이 없어 1회용 토큰(D)보다 만들고 운영할 것이 적다.

## 포기한 것
- 카드 QR 사진이 퍼지면 그 학생으로 들어갈 수 있다. 인쇄된 카드 사진이 퍼진 것과 같은 수준이고, 대응은 개인 코드 재발급이다. 재발급하면 자동 로그인(refresh)은 바로 끊기지만, 이미 받은 접속은 최대 30분, 음원 쿠키는 최대 2시간까지 남는다.
- 카드를 잃어버렸을 때 같은 QR을 다시 인쇄할 수 없다. 재발급하고 새 카드를 인쇄해야 한다.
- 반 QR이나 링크가 반 밖으로 퍼지면 가입 코드가 퍼진 것과 같다. 대응은 가입 코드 재발급이고, 재발급하면 예전 QR·링크로는 들어올 수 없다.
- 옛 카드·옛 반 QR이 남아 있으면 실패가 쌓인다. 개인 코드 실패는 (반, IP)로 세므로 같은 교실 IP의 반 전체가 10분 잠길 수 있다. 같은 값 재전송 막기와 문구(지킬 것 7)로 줄이지만 없애지는 못한다.
- 수업 중 한꺼번에 찍으면 반 이름이 안 보일 수 있다(지킬 것 4).
- fragment 지우기는 주소창과 현재 탭 기록에서만 지운다. QR을 읽은 카메라 앱이나 브라우저 전체 방문 기록에 처음 주소가 남는지는 기기마다 다르다.

## 재검토 조건
- 카드 QR 유출로 대신 듣기가 실제로 생기면 1회용 토큰(D)을 검토한다.
- 카드 분실 재발급이 잦아 교사 부담이 크면 개인 코드 다시 보기(0022 재검토 조건)와 함께 본다.
- 교실에서 가입 코드 확인 429가 실제로 자주 나면 확인 API도 로그인처럼 없는 가입 코드일 때만 세도록 바꾼다.
- 교실 IP 하나 때문에 반 전체 잠금이 실제로 생기면 실패 잠금 기준(0022 재검토 조건)과 함께 본다.
