# 0005. `user` 단일 테이블 + `auth_identity` 분리

- 상태: 결정 · 날짜: 2026-11-01

## 배경
학생(코드)·교사(비밀번호)·향후 학부모(소셜 로그인)의 인증 수단이 다르다.

## 선택지
### A. student / staff 테이블 분리
- 장점: 역할별 컬럼이 명확
- 단점: 반 배정·권한·소속 조회가 테이블마다 갈라짐
### B. user 단일 + 인증 컬럼 nullable
- 장점: 테이블 하나
- 단점: 인증 수단이 늘 때마다 user 변경
### C. user 단일 + auth_identity 테이블
- 장점: 반 배정·권한·소속이 한 테이블에서 끝남. 인증 수단 추가 시 user 변경 없음
- 단점: 로그인 시 조인 1회

## 결정
C.

## 근거
조인이 단순하고, 소셜 로그인 추가 시 user를 바꾸지 않는다. 실패 횟수·잠금도 수단별로 관리할 수 있다.

## 포기한 것
역할별 전용 컬럼의 명확함.

## 재검토 조건
역할별 컬럼이 10개 넘게 갈라지면 프로필 테이블 분리.
