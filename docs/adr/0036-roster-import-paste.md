# 0036. 학원 명단 표를 붙여넣어 반·학생을 한 번에 생성, 절반만 생기는 일 없음

- 상태: 결정 · 날짜: 2026-11-24

## 배경
- 학원이 처음 이 앱을 쓸 때 반·학생 명단은 이미 엑셀·구글 시트 등에 있음. 양식은 학원마다 다름
- 지금 등록 방법
  - 반: `POST /api/v1/admin/classes` 한 번에 하나. 권 코드(`L2-B1`)·개강일·수업 요일·담당 교사 필수, 진도표(`class_session` 24행, 블랙 28행)·가입 코드 자동 생성
  - 학생: `POST /api/v1/admin/classes/{id}/students` 반마다 1~50명, 응답에만 개인 코드 평문(0022)
  - 반 10개·학생 150명이면 화면 이동 수십 번
- 학생 명단 파일 업로드는 처음 범위 정할 때 2차로 미뤘던 항목. 학원 운영 쪽 요청으로 1차에 포함
- 쓰는 때: 학원이 처음 시작할 때와 새 반을 추가할 때. 시즌이 바뀔 때는 같은 반이 다음 권으로 넘어가므로 이 기능 대상 아님(별도 결정)

## 선택지
### A. 서버가 xlsx·csv 파일 읽기
- 장점: 파일 하나만 올리면 됨
- 단점: 열 순서·제목이 학원마다 달라 결국 사람이 열을 골라야 함. 파일 형식별 처리 필요
### B. 화면이 기존 두 API를 차례로 호출
- 장점: 서버 변경 없음
- 단점: 4번째 반에서 실패하면 앞의 반 3개만 생성된 상태. 다시 누르면 같은 반 두 번 생성. 사용권 학생 수 한도(0031)는 만들어 봐야 앎
### C. 붙여넣기는 화면, 검사와 생성은 새 API 한 트랜잭션
- 장점: 전부 생성 또는 전부 취소. 만들기 전에 서버 규칙(권·교사·사용권·이름 겹침) 검사 결과 표시
- 단점: API 2개 추가, 기존 반 생성·학생 등록 경로를 함께 묶는 조립 코드 필요

## 결정
C. 표 프로그램에서 복사한 글자(줄 = 학생, 탭 = 칸)를 화면이 해석하고, 관리자가 열의 뜻(이름·반·학교·학년)과 반마다 기존 반·새 반을 정한 뒤 서버로 전송.

| 경로 | 동작 |
|---|---|
| `POST /api/v1/admin/roster-imports/check` | 검사만, 생성 없음. 200 + `errors[]`·`warnings[]` |
| `POST /api/v1/admin/roster-imports` | 생성. 오류가 있으면 아무것도 만들지 않고 첫 오류로 4xx. 성공 201 + 반별 가입 코드·새 학생 개인 코드 |

요청 본문(두 경로 같음)
```json
{
  "classes": [
    { "existingClassId": 12,
      "students": [ { "name": "김민준", "school": "A중", "grade": "중1" } ] },
    { "newClass": { "name": "블루 화목반", "bookCode": "L3-B1", "startDate": "2026-12-01",
                    "weekdays": [2, 4], "teacherIds": [3] },
      "students": [ { "name": "이서연" } ] }
  ]
}
```
- 반 항목마다 `existingClassId`와 `newClass` 중 하나만. `newClass`·`students[]` 칸과 검사는 기존 반 생성·학생 등록 요청과 같음
- 한도: 반 30개, 반마다 학생 50명, 전체 500명

검사
| 구분 | 내용 |
|---|---|
| 오류 | 칸 형식, 없는 권 코드, 그 학원 활성 교사 아님, 다른 학원 반(404), active 아닌 반(`CLASS_NOT_ACTIVE`), 사용권 기간 밖(`LICENSE_INACTIVE`), 권별 학생 수 초과(`LICENSE_SEATS_FULL`, 가져오기 전체를 권별로 합산) |
| 오류 | 같은 이름·학교·학년이 요청 안에 두 번(같은 반이든 다른 반이든). 문구에 고칠 줄 표시: "김민준(A중·중1)이 그린 월수반과 블루 화목반에 모두 있어요. 한 반만 남겨 주세요" |
| 경고 | 학원에 같은 이름의 active 학생이 이미 있음(같은 명단 두 번 붙여넣기·동명이인). 생성은 막지 않고 화면이 체크로 한 번 더 확인 |
| 경고 | 새 반 이름이 학원의 active 반 이름과 같음 |

생성
- 학원 관리 쓰기 잠금 → 검사 → 새 반 생성(진도표·가입 코드) → 학생 생성·개인 코드 발급 → 반 등록, 한 트랜잭션
- 이미 등록된 학생을 찾아 새 반으로 옮기지 않음. 새 학생만 생성
- 감사 로그 한 줄: `roster_import`, detail `{"createdClassIds":[…],"existingClassIds":[…],"createdStudents":n}`(이름·코드 없음)
- 개인 코드 평문은 생성 응답에만, 로그·감사에 없음(0022)

## 근거
- 열을 사람이 고르면 학원마다 다른 양식 대응. 복사한 글자는 엑셀·구글 시트·한셀 모두 같은 형식이라 파일 형식 처리 불필요
- 처음 쓰는 관리자에게 반만 절반 생긴 상태가 가장 혼란. 한 트랜잭션이면 고치고 다시 누르기만 하면 됨
- 사용권 학생 수 한도는 여러 반에 걸쳐 같은 권이면 합쳐서 봐야 함. 반마다 따로 부르면 마지막 반에서야 초과를 앎
- 두 반에 같은 학생을 막는 쪽은 나중에 넓히기 쉬움. 허용했다가 잘못 합쳐진 청취 기록은 되돌리기 어려움
- 만들기 실패를 첫 오류 하나로 두는 이유: 화면이 늘 check를 먼저 부르므로 만들기 실패는 그 사이 다른 관리자가 바꾼 경우뿐. 공통 오류 형식(`errors[]`는 400 `VALIDATION`만) 유지

## 포기한 것
- 파일 업로드, 반 이름에서 권·요일 자동 추출, 한 칸에 섞인 정보 나누기
- 기존 학생 자동 이동(같은 이름이면 경고만)
- 한 학생의 두 반 동시 등록(가져오기에서만, 반 이동 등 기존 기능은 그대로)
- 멱등 키(두 번 전송은 화면 버튼 잠금과 이름 겹침 경고로 대응)

## 재검토 조건
- 두 반 수강이 있는 학원이 생기면: 서버 검사에서 같은 이름·학교·학년을 한 명으로 합쳐 여러 반에 등록, 학생 수는 한 번만 셈. 요청 모양은 그대로
- 반 30개·학생 500명을 넘는 학원이 생기면: 한도와 진도표 생성 시간 다시 측정
- 같은 명단 두 번 붙여넣기가 경고에도 계속 생기면: 서버 강제 확인(요청 칸 추가) 검토
