# 콘텐츠 manifest 만들기

녹음된 교재 자료 폴더에서 회차별 manifest와 업로드용 음원 폴더를 만든다(ADR 0027). 교재 원문과 음원은 저장소에 넣지 않으므로 출력 폴더는 저장소 밖에 둔다.

```bash
python -I -X utf8 scripts/content/build_manifest.py <자료 폴더> <출력 폴더> [--only L2-B1-05,K-B1-S1]
```

## 출력
- `manifest/{회차 코드}.json`: 회차 제목, 지문(제목·문장·목소리 4개 트랙의 길이와 문장 길이), 회차 어휘(단어·품사·뜻·예문·예문 해석·음원 키). 앱의 콘텐츠 import 실행기가 읽는다
- `audio/{회차 코드}/…`: S3 키 이름 그대로 둔 음원(하드 링크, 안 되면 복사)
  - 지문 `{코드}_p{n}_{목소리}.mp3`(목소리 `us_w` `us_m` `uk_w` `uk_m`)
  - 단어 `{코드}_w{nn}_us_w.mp3`, 예문 `{코드}_w{nn}_ex_us_w.mp3`
- 표준 출력: 회차·지문·음원 수와 크기, 문장 사이 간격(지문 전체 길이 − 문장 길이 합) ÷ (문장 수 − 1)의 분포

## 규칙
- 회차 코드는 DB 코드다. 자료의 블랙 `L5-…`는 `K-…`로 바꾼다
- 품사 `n.` `v.` `adj.` `adv.` `prep.` `conj.` `구` → `n` `v` `adj` `adv` `prep` `conj` `phr`. 그 밖은 오류
- 화자가 내레이터면 `speaker`는 null
- 문장 파일 수가 문장 수와 다르거나, 간격이 0~3000ms 밖이거나, 칸 길이가 DB 한도를 넘으면 그 회차는 만들지 않고 오류로 보고한다(종료 코드 1)
- 표준 라이브러리만 쓴다. mp3 길이는 프레임 수로 센다
